# Keitaro wrapper

Обёртка над рекламным трекером [Keitaro](https://keitaro.io): быстрое создание
кампаний по шаблону и редактирование офферов без ручной работы в админке.

## Что делает

1. **Создаватор кампаний** — по названию, гео-коду страны и ID оффера создаёт
   кампанию с двумя потоками:
   - первый — условный: ловит всех из выбранной страны и редиректит на Google;
   - второй — дефолтный: ротация офферов с долями (share).
   Домен, группа и источник подтягиваются из API (группа/источник создаются
   автоматически, если их нет). Имена кампаний получают префикс
   `test_mkrtchyan_`.
2. **Редактор офферов** — добавление и удаление офферов в потоке ротации
   существующей кампании. После каждого изменения доли (share)
   пересчитываются равными долями так, чтобы сумма была ровно 100 (3 оффера →
   33.33 / 33.33 / 33.34).

Каждое действие (создание, добавление, удаление) пишется в локальную БД —
журнал действий виден в интерфейсе.

## Стек

- Backend: FastAPI + SQLAlchemy 2 + Alembic (SQLite по умолчанию)
- Клиент Keitaro: httpx (Admin API, заголовок `Api-Key`)
- Frontend: HTML + vanilla JS (без сборки)
- Тесты: pytest + httpx.MockTransport (реальный ключ не нужен)

## Запуск

Нужен Python 3.11+.

```bash
pip install -r requirements.txt
cp .env.example .env          # затем вписать KEITARO_API_KEY
alembic upgrade head          # создать таблицу журнала
uvicorn app.main:app --reload
```

Открыть http://127.0.0.1:8000

Ключ API создаётся в админке Keitaro: **Профиль → API ключи → Создать новый ключ**
(см. скриншот в ТЗ). Ключ и URL задаются только в `.env`, в код не зашиты.

### Демо без реального Keitaro

```bash
python scripts/mock_keitaro.py   # поднимает mock на 127.0.0.1:8081
# в .env: KEITARO_BASE_URL=http://127.0.0.1:8081
```

## Миграции

Миграции — Alembic. Таблица журнала `campaign_actions` создаётся миграцией
`0001_init`:

```bash
alembic upgrade head        # применить все миграции
alembic revision --autogenerate -m "..."   # новая миграция после изменения моделей
```

`app.main` при старте также выполняет `create_all` — этого достаточно для
тестов, но правильный путь для прод-БД — `alembic upgrade head`.

## Проверено на живом инстансе

Обёртка прогонялась против рабочего Keitaro (FastAPI-запросы с `Api-Key`):
кампания создана со всеми потоками и настройками, структура сверена в админке
(условный поток с фильтром страны → редирект, дефолтный поток с ротацией
офферов, `share` в элементах ротации).

## Тесты

```bash
python -m pytest tests/ -v
```

Тесты идут против mock-транспорта (httpx.MockTransport): проверяют сборку
payload'а кампании (порядок потоков, фильтр страны, редирект, ротация),
математику весов (сумма ровно 100), добавление/удаление офферов, guard'ы
(дубль, последний оффер, отсутствующий оффер) и работу API обёртки с журналом.

## Известные ограничения

- Гонки без блокировок: создание группы/источника (check-then-create) и
  редактирование кампании (GET → мутация → PUT) не защищены от параллельных
  запусков — на общем инстансе возможен дубль группы или потеря чужой правки.
  Для тестового задания принято; рабочий вариант — версионный контроль
  (If-Match/updated_at) и уникальный индекс на имя группы.
- UI обёртки не имеет авторизации: это внутренний инструмент, запускать стоит
  на доверенной машине/сети.

## Решения по ТЗ

- **Белый список полей в PUT.** Обновление кампании отправляет только
  редактируемые поля (name, group_id, source_id, domain_ids, state, cost_*,
  schema) — read-only поля GET-ответа (id, created_at) в PUT не уходят.
- **Пагинация списков.** Инстанс общий для всех кандидатов (сотни кампаний),
  у всех справочников явно поднят лимит 1000.
- **Ресурсы.** Клиент Keitaro создаётся на запрос и закрывается после него
  (async-зависимость с `aclose`).

- **Доли офферов (share).** После добавления/удаления оффера доли пересчитываются
  равными долями (сумма ровно 100, остаток достаётся последнему). Поле доли в
  живой схеме Keitaro называется `share` — сверено GET'ом реальной кампании
  инстанса. Альтернатива — сохранять доли остальных и делить остаток новому:
  у пары офферов цифры совпадают, при трёх и больше поведение задокументировано
  здесь.
- **Порядок потоков.** Условный поток (гео → Google) всегда первым,
  дефолтный (офферы) — последним: Keitaro отдаёт трафик первому совпавшему
  потоку.
- **Группа/источник.** Имена задаются в `.env` (`FORTESTS` из ТЗ); при
  отсутствии в Keitaro создаются автоматически.
- **Префикс имён.** `test_фамилия_` из ТЗ: если имя не начинается с префикса,
  он добавляется автоматически.
